# Short IQ examples

Public examples are prepared as a city/village pair from the same nominal recording time. Each excerpt normally contains **one second** of unmodified interleaved little-endian int16 I/Q. At 10 MS/s this is exactly 40,000,000 bytes per station, or 80,000,000 bytes for the pair, excluding metadata.

Generate excerpts from selected original recordings using [extract_iq_examples.py](../tools/extract_iq_examples.py).

## Selection

A default start offset of 10 s places the example after the initial PPS marker interval. The same sample offset is used for both stations. Excerpts selected this way are **not additionally aligned using PPS or cross-correlation**. They illustrate reception and loading; comparing their frame counts does not directly estimate reception loss.

Preserve the original recordings in the archive. The tool only reads the selected interval and writes separate excerpt files; it does not resample, normalize, filter, demodulate, or change the sample values.

## Generated files

| Path | Contents |
| --- | --- |
| `city/<source_stem>_excerpt.raw` | Extracted city I/Q samples |
| `city/<source_stem>_excerpt.json` | Derived excerpt metadata, sample offset, length, and RAW hash |
| `city/<source_stem>_source.json` | Byte-for-byte copy of the original recording JSON |
| `village/…` | Equivalent village files |
| `pair_manifest.json` | Shared selection, source identification, and timing limitations |
| `checksums.sha256` | Hashes of the seven generated payload/metadata files, relative to this directory |

The extractor refuses to overwrite any of these outputs. Use a new destination for another pair. To distribute the examples under this directory, copy the generated files alongside this README after reviewing them.

## Metadata and timestamps

`*_excerpt.json` uses the `iq_excerpt_metadata` schema rather than pretending to be original recorder metadata. `sample_rate`, `center_freq`, `gain`, and `format` retain their source meanings; `samples_recorded` is the excerpt length. `start_sample_zero_based`, `actual_start_offset_s`, and `actual_duration_s` describe the exact selected sample range. Requested times are rounded to the nearest complex sample using decimal half-up rounding.

Original software timestamps appear as `source_start_iso` and `source_start_unix`. They are not rewritten as verified first-sample timestamps for the excerpt. Environmental values are copied from the source recording, not newly measured for the one-second interval. Full original metadata remains in `*_source.json`.

Excerpt filenames deliberately include `_excerpt` and are not intended for automatic discovery by the original full-recording batch scripts. A reader should use the explicit paths and excerpt JSON fields. For MATLAB, the [binary loading example](../../docs/data_formats.md#7-matlab-loading-example) applies with `start_sec=0`, `duration_sec=1`, and the excerpt paths. The source's 10 s offset has already been applied and must not be applied again.

The checksum list generated by the tool covers its own outputs, not this README or any later additions. Regenerate it if generated files are subsequently edited.
